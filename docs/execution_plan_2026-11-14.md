# 四周执行计划：可修复的人审范围生成与最小实验

制定日期：2026-11-14（Asia/Shanghai）。
用户选择：4 周，优先核心机制与最小实验。
排期窗口：2026-11-14 至 2026-12-11。此窗口是从当前日期计算的工作计划，不代表已确认的学校截止日期。
协作假设：按现有三人小组分成工程、机制、实验三个负责人；以下为建议分工。

## 1. 四周目标与范围

主目标：在现有 AgentScope + MA-Crafter 基础上，实现“受高层字段权限与联合任务约束限制的人审范围生成”，并完成可复现的小规模比较。

四周结束应交付：

1. 可运行的约束诊断、有限自动修复、计划级人工审阅、执行反馈闭环。
2. 报告原有范围覆盖策略与新范围生成策略的可切换实现。
3. 可满足 / 当前模型内不可满足 / 未知三值结果，包含依据、适用时域及计划版本。
4. 五组主对照、关键消融、逐局数据和分析。
5. MA-Crafter 端到端证据；CUBE 优先完成同一机制的最小迁移，设第一周接入检查点。
6. 与实际代码和结果一致的最终报告实验章节初稿。

完成标准是正确实现、可复现比较和如实解释结果。显著提升、人类一定优于自动修复均不作为预设结论。

本轮固定 AgentScope、LLM、记忆、通信和角色策略。暂不做记忆/通信消融、模型训练、仓库环境或复杂可视化界面。
审阅上下文采用足够清楚的基础版本，不把最小证据生成作为本轮必须完成的第二项创新。
局部暂停、异步人审及增量重校验留待后续；第一版统一全局暂停所有环境副作用。

相关依据：[近期文献与候选创新审查](innovation_review_2026-11-14.md)。

## 5. 最小技术切片

### 5.1 计划与信息边界

拟增加独立 coordination 模块，避免将检查和人审逻辑混进 AgentScope 基类。建议先形成以下接口：

- Plan：Agent、计划标识、版本、目标、支持的高层字段、剩余技能/当前技能、状态和已有承诺。
- Snapshot：在线可用事实、事实来源及时间、所有相关剩余计划。
- Diagnosis：要求类别、状态、证据、受影响计划与未知信息。
- ScopeResult：候选范围、可编辑字段、求解状态、依据/候选改法、适用时域。
- ReviewRequest：唯一标识、快照版本、编辑范围、展示上下文、额度与超时。
- ExecutionEvent：实际动作、物理变化、任务进展和结束原因。

只开放环境实际支持的高层修改。MA-Crafter 先考虑目标材料、分享对象、允许的操作或重规划请求；CUBE 参与者/时序字段须经接口核对后决定。不存在的截止时间、能力或游戏规则不能补造进模型。

在线选择器和审阅者使用同一信息池。完整模拟器状态只在隔离的离线评估中用于标注。

### 5.2 约束与范围生成

优先实现少量可验证的约束和有限修改域，不在四周内构建通用长时域规划求解器。

- 游戏规则、不可编辑字段和未选中计划的承诺保持固定。
- 从已诊断约束关联到可改变这些条件的字段，生成候选修改。
- 对候选范围联合检查参与、资源、时序和依赖，而非逐 Agent 分别检查后直接拼接。
- 目标缺陷的解决条件必须明确，避免全部等待被当作有效修复。
- 第一个版本不允许人审之外的计划被悄悄重写；若自动传播修改，须按固定政策另行校验和记录。
- 先枚举小范围；4 Agent、最多编辑 2 个，对应 11 个含空集的范围。
- 最小性与可满足性结论仅在声明的字段域、模型和局部规划时域内成立。
- 检查结果为 unknown 时，不包装为已证明可行或不可修复。

SMT 或 CP-SAT 是实现选项，D3–D7 依据编码适配选择其一，不同时维护两套求解后端。

### 5.3 强自动修复 B

B 与 C/D 使用同样的诊断、允许操作与自动修复限额。

先尝试能直接执行的程序化/求解器修复；再进行有界定向重规划。人工不接管已被自动解出的简单问题。
自动修复轮数初始设为 2，求解超时与 token 限额在预实验后冻结，记录实际消耗。
保留一个“增加自动推理/重规划、不提供人类修改”的控制，检验收益是否仅来自更多尝试。

### 5.4 最小人审与事务

先用 CLI 或简单本地表单完成闭环，不开发复杂网站。

- 请求发出时计费；超时、拒绝和无效回复同样保留。
- 同一请求重开不重复收费。
- 人只能修改授权字段；阅读额外计划不扩大编辑权限。
- 审阅期间暂停全部环境副作用，包括资源交换。
- 校验版本、字段权限、前置条件和受影响承诺后，联合激活修改。
- 记录批准、校验通过、局部进展、缺陷恢复、最终完成等不同事件。
- 额度耗尽、超时和无效回复使用固定的等待/重规划/未解决策略，不削弱共同合法性保护。

## 6. 必需的机制验证

以下是正确性与研究假设的检查，不以测试数量代替证据：

| 案例 | 应验证的结论 |
| --- | --- |
| 只改一个计划即可修复 | 不强制把所有相关参与者都纳入人审 |
| 必须联合改变两个计划 | 容量足够时能找到完整范围，单改不被误判可行 |
| 容量小于必要修改数 | 在声明模型内返回不可修复/超出容量 |
| 共享参与者、资源或时序存在耦合 | 局部可行的候选不会未经联合检查就被接受 |
| 证据缺失 | 返回 unknown，并保留缺失依据 |
| 求解超时 | 返回 unknown，耗时计入开销 |
| 越权字段、过期计划版本 | 修改被拒绝，环境不受该回复影响 |
| 重复请求/重复提交/半组提交 | 不重复收费或执行，联合修改不部分生效 |

自然案例用于判断实际适用性；受控案例用于解释机制。目标收集约 30–50 个去重快照，但记录实际数量及来源局数，不将一局中的多个快照当作独立重复。

## 7. 最小实验矩阵

五组在同一环境内固定模型、提示中的无关部分、记忆、通信、角色策略、合法性保护、步数和时间限制。

| ID | 条件 | 用途 |
| --- | --- | --- |
| A | 自主规划与执行，共同保护与被动诊断日志 | 基础对照 |
| B | A + 强约束自动修复 | 自动修复收益及人工必要性的参照 |
| C | B + 符合资格事件上的全团队人工审阅 | 较大编辑容量的参考 |
| D0 | B + 报告原有完整集合覆盖选择 | 核心创新的直接对照 |
| D1 | B + 权限域内范围生成与联合可修复性检查 | 本轮主方法 |

主要比较：

- B 对 A：自动修复作用。
- D1 对 B：人工辅助在强自动基线上的附加作用。
- D1 对 D0：范围生成与检查的作用。
- D1 对 C：任务表现与人工时间的权衡。

C 与 D0/D1 统一触发资格、信息、允许字段、校验、自动修复政策和请求次数。C 展示全部可编辑计划；D 限制范围并允许弃权，因此 C 是更大编辑容量的参考，不称为等范围比较。

必要消融：

1. 在冻结快照上比较随机、风险排序、D0 覆盖选择和 D1。
2. D1 保持候选池不变，关闭联合约束，仅做局部检查，定位跨 Agent 约束的作用。
3. 区分新增候选范围带来的收益与仅筛除不可行候选带来的收益；若无法完全分离，明确将结果解释为模块整体增益。
4. 保留自动执行候选改法及纯重规划控制。

共同合法性保护始终开启，不用非法执行的基线制造优势。

## 8. 预算、样本与参数

### 8.1 初始参数

- 主实验先用 4 Agent；每次选择性审阅最多编辑 2 个 Agent 的计划。
- 每局最多发出 2 次审阅请求；空范围不产生请求。
- MA-Crafter 正式候选步数上限为 350，先用短运行联调。
- CUBE 使用其规则下可解场景，在预实验后确定统一上限。
- 人审超时、自动修复 token/时间限额、求解超时和停止条件均于 D21 前冻结。
- 人工时间包含在总墙钟时间内，同时单列计算、等待、阅读和修改时间。
- 请求数不是人工秒数的替代指标。

以上参数是起始计划，可在预实验中依据可解性和成本统一修改；冻结后不按实验组分别放宽。

### 8.2 实验量

目标档：每环境 5 条件 × 5 地图种子 × 2 次独立运行 = 50 局。
两个环境都接通时，目标合计 100 局。

保底档：每环境 5 条件 × 3 地图种子 × 2 次独立运行 = 30 局。
两个环境合计 60 局。此档定位为小规模探索，不能据此作广泛稳定性或人群结论。

冻结快照的选择策略检查尽量离线完成，不把所有策略都扩展成一整套昂贵的人审整局实验。
优先减少重复量，保持关键对照完整；保留失败，不只补跑表现差的组。

D5 先计量短运行；D18–D21 根据整局预实验确定目标档或保底档。估算使用实际聊天/Embedding 请求数、token 和耗时，批量运行规模以测量后的成本和可用预算为依据。

### 8.3 人审安排

- 第一周确定可参与者与可投入时间，第三周开始统一训练和小试。
- 优先有 4–6 名审阅者；若只能由小组成员参与，明确标注为内部可行性试验。
- 每人不连续重复审阅同一快照；条件顺序尽可能平衡，记录经验差异。
- 人审条件使用相同的审阅者可用性和请求排队规则，等待时间单列并计入总耗时。
- 脚本回复用于事务与预算测试，不能作为真实人类有效性的证据。
- 审阅者不足时可完成系统和机制结果，人工效果保持未验证，不以 LLM 扮演人补充人类样本。

## 9. 记录、指标与分析

实验清单至少包含：

experiment_id、环境与版本、seed、repeat_id、代码版本及实际源码摘要、提示摘要、模型设置、condition、scope_policy、K_H、B_H、修复限额、求解限额、步数上限、墙钟上限和信息边界。

每局和每次审阅保留：

episode_id、plan_id/version、实际动作与进展、诊断状态与证据、候选及选中范围、求解结果、请求 ID、预算变化、展示上下文、修改、拒绝原因、提交版本、缺陷恢复及结束原因、聊天和 Embedding 消耗。

主指标：

- MA-Crafter：任一 Agent 实际获得钻石的团队成功率、里程碑进展。
- CUBE：全部方块交付成功率与实际交付比例，成功推动不等同于交付。
- 效率：包含人审时间的总完成时间；失败局保留；同时报告统一上限下的进展。
- 机制：范围内可修复率、缺陷恢复、无效/超时/弃权请求、求解开销。
- 人工：请求、展示计划、直接编辑计划、阅读及修改秒数。
- 可靠性：新冲突、越权或过期提交、重复执行、技术错误。

对同种子配置配对，按整局统计；同图重复和同一审阅者的重复参与在分析中处理。报告效应量与不确定区间，小样本不以单个显著性数字作为主要结论。

输出至少包括主结果表、任务表现与人工时间图、范围选择/联合检查消融，以及正反失败案例。环境间分别报告，不合并为一个不透明分数。

## 10. 检查点与取舍

| 检查点 | 继续条件 | 条件不足时的处理 |

| D14：核心正确性 | 三值结果、权限边界及联合约束通过验证；强 B 可运行 | 暂停新增界面和次要功能，集中修复核心，降低实验量 |
| D21：实验冻结 | A/B/C/D0/D1 可跑、事务有效、预算与样本计划可承受 | 切换保底样本；人审不可用则只报告系统可行性和机制结果 |

额外研究判断：

- 若自动执行候选修复已经取得相同效果，不削弱 B；报告人工没有额外收益，贡献转向范围生成与诊断。
- 若 D1 相对 D0 收益很小但开销较大，不强行包装优越性；分析有效和失效条件。
- 四周内不因看到某个种子的结果而增加新模块、改主指标或挑选场景。
