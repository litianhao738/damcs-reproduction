# 近期文献与候选创新审查

检索日期：2026-11-14。针对本项目的 MA-Crafter、CUBE、约束诊断、有限自动修复和选择性人工审阅。
本文件区分已发表/公开工作的内容与本项目的候选研究方案。候选方案尚未实现或验证；本轮主题检索不构成“首次提出”的证明。

## 1. 建议与研究边界

优先研究“从任务约束生成可修复的人工编辑范围”，以“最小充分审阅证据”作为配套。
“局部暂停与增量重校验”是工作量较大的架构备选，须由真实审阅等待损失支持。

中期报告已经提出完整关联计划组、有限请求预算、版本校验、联合提交和执行结果追踪。这些内容属于已有方案，不能在新增贡献中重复计数。AgentScope 作为统一运行底座，所有实验组保持一致。

本项目的核心问题可以收敛为：

> 面对耦合的剩余计划，系统如何确定哪些高层字段确实存在可行改法，向人展示足够判断的证据，并确保修改在生效时仍适用？

先建立强自动修复基线。如果求解器能直接生成可执行修复，默认先自动执行；人工的额外价值必须用执行结果建立。

## 3. 候选一：在编辑权限约束下生成可修复范围

### 3.1 现有方案的具体缺口

报告的覆盖目标依赖候选完整修改集合 R_j。需要进一步回答：

- R_j 如何从当前计划与约束产生，而非主要靠人工模板？
- 覆盖多个问题的完整集合之后，所有改动能否在同一个状态下共同成立？
- 选中范围是否有权修改真正需要改变的字段？
- 缺失证据时，系统是否把未知前提当成可满足条件？
- 一个很严重的问题，是否在当前容量、操作范围和规划时域内根本无法修复？

高风险与可修复是不同变量。问题很严重，并不意味着把它交给某个小范围的人审就有用。

### 3.2 最小实现

给每个 Agent 的剩余高层计划建立有限变量域：任务目标、允许选择的参与者、支持的时序参数和技能序列。游戏规则、不可编辑字段和已经生效的事实是硬约束。

设当前计划为 p，选中范围为 S，人类允许的字段域为 D_H(S)，在线可用事实为 O。验证：

$$
\exists p'_S \in D_H(S):
\Phi(p'_S,p_{-S};O)
\land \operatorname{Resolve}_j(p')
\land \operatorname{PreserveValidWork}(p').
$$

Phi 需要包括跨 Agent 的参与、时序、资源和依赖约束。Resolve_j 对应声明的局部缺陷或规划时域内的进展条件，避免“全部等待”被当作修复。

第一版保持未选中高层计划不变。如果允许自动传播修改，必须把固定传播策略和实际修改范围纳入验证与日志。

求解返回三种结果：

- 可满足：存在模型范围内的改法，保存证据和候选改法。
- 不可满足：在当前编码、时域和权限域内无解，保存冲突原因。
- 未知：证据缺失、编码不覆盖或求解超时；不能当作不可满足，也不能当作已证明可行。

未知世界事实不得通过任意赋值偷偷满足约束。证书须标记依赖的观测、假设、计划版本和时域。它证明的是显式模型下的性质，不保证真实环境中的最终成功。

小团队可先枚举候选范围：6 个 Agent、最多编辑 2 个，对应 22 个包含空集的范围。先做精确小规模验证，再考虑近似算法。

### 3.3 人工的必要性必须单独成立

如果候选改法已经可以直接执行，应纳入自动修复基线。不能为了保留人工环节，刻意把已求解的问题交给人。

人审可能有价值的部分是模型未充分表达的长期选择、可行方案间的权衡和自动修复持续失败后的判断；这些优势需要实验验证。所有组使用相同在线信息，不能通过给人全图、答案或额外工具制造优势。

### 3.4 成立所需的对照与消融

固定失败快照、在线信息和权限域，比较：

1. 单体风险排序。
2. 报告原有完整集合覆盖选择。
3. 仅做局部候选可行性筛选。
4. 加入跨任务、共享资源和时序的一致性检查。
5. 自动执行求解器生成的候选修复。
6. 在强自动基线上加入预算化人工审阅。

始终保留共同的动作合法性保护。这里消融的是范围生成与准入证书，不是放开非法执行。

主要指标：范围内可修复比例、无效审阅请求、实际缺陷恢复、求解耗时、人工时间和总任务表现。离线完整状态可用于标注评估真值，不能进入在线选择器。

### 3.5 反驳条件与创新边界

如果模板已经完整准确、约束稀疏、几乎所有候选范围都可修复，证书的边际收益可能很小。若检查成本超过节省的人审成本，应简化。

真正可主张的候选贡献是：从合作约束与字段权限生成并验证审阅机会，并研究这种结构先验何时比风险排序和固定机会分配更有效。不能把“使用 SMT”或“保证人一定修好”作为贡献。

## 4. 候选二：为选定编辑范围生成最小充分审阅证据

这是候选一的配套，只有在真实阅读成本显著时才值得作为独立研究点。

### 4.1 必要性

可编辑范围 S 很小，不代表审阅上下文 N(S) 很小。判断是否把工具交给一个 Agent，可能需要查看其他 Agent 的承诺、前置条件和已失败动作。全量日志增加阅读成本，简单截断又可能遗漏关键条件。

中期报告的成本函数已经计入额外上下文，新增工作应是构造这个上下文，而不是再次提出“人有阅读成本”。

### 4.2 具体机制

由冲突核、候选改法的必要前提和受影响承诺，构成审阅证据：

- 当前要解决的要求及证据状态。
- 人可以修改的字段与范围。
- 相关事实、计划片段、版本和剩余承诺。
- 修改可能影响的其他计划。
- 仍然未知的信息。

编辑授权与阅读可见范围分别记录。看到其他计划不授予修改权。

“充分”先限定为模型层面的充分性：保留影响本次约束判断和修改适用性的必要前提。它不是对真实人类理解或决策质量的自动保证。摘要不得引入快照中不存在的事实。

可以在模型中寻找最小证据集合，再从真实试验测量阅读时间，检验报告中的线性成本代理是否成立。

### 4.3 验证

固定 S、任务快照、界面和可修改字段，对照：

1. 全量关联上下文。
2. 等长度截断或检索。
3. 等长度 LLM 摘要。
4. 由约束证据生成的审阅上下文。

同时看阅读加修改时间、修复成功、遗漏依赖、新冲突和用户理解。比较压缩方法时匹配 token 或显示长度；不能把文本更短直接解释为证据更好。

如果降低时间却明显增加错误，则不成立。若等长度摘要已达到同样效果，该机制应作为界面实现，而非独立算法贡献。

最小解释已有先例，差异必须落在与具体编辑权限、联合修复和执行验证相连的证据构造上。

## 5. 候选三：局部暂停与增量重校验

这是高工作量的架构备选。报告当前的全局暂停是合理的第一版；新协议需要先证明存在显著等待损失。

### 5.1 必要性

人审耗时可能使无关 Agent 一起等待。完全不暂停又可能让资源、参与者或时序变化，使返回的人类修改过期。

通用版本号、乐观并发控制或局部修复已有研究。候选差异应集中在耦合的高层计划、持续环境动作、人工延迟和不可逆动作条件下，暂停范围如何确定。

### 5.2 具体机制

分开记录：

- S：人可编辑的计划。
- E：本次审阅依赖的事实与承诺。
- P：为保护 E 而必须等待的执行范围。

按技能的实际读写范围和依赖关系计算 P。无关 Agent 可以继续执行；影响 E 的修改受约束或触发失效。人类回复返回后，只重查发生变化的相关条件，并原子激活联合修改。

必须覆盖所有状态变化路径，包括 env.step 之前发生的资源交换。读写范围不完整、外生变化无法受控或未知依赖过多时，回退到更保守的暂停。

### 5.3 可证明范围与限制

在所有副作用都经过执行器、技能读写范围完整、相关外生变化可检测的假设下，研究：

- 无关执行不会改变受保护的审阅前提。
- 过期回复不会修改已经不匹配的计划。
- 联合修改不会只提交一部分。

这不保证人类方案有效，也不把物理动作假设为可以随意撤销。

### 5.4 验证

同一审阅输入与延迟，比较：

1. 全局暂停并完整重校验。
2. 乐观继续执行，返回后做版本检查。
3. 仅按消息关系局部暂停。
4. 按实际执行依赖局部暂停并增量重校验。

测量总完成时间、被阻塞的 Agent 时间、过期审阅率、重新请求、额外冲突和非法提交。

模拟延迟用于验证协议；真实人工数据用于评价人工负担。区分可暂停世界与固定时钟世界：所有组使用相同世界推进和外生事件规则，不能让一个组在审阅期间冻结生命值，另一个组继续消耗，却把差异全部归因于协议。

若团队高度耦合、几乎没有独立工作，或人工等待占比很低，局部暂停的优势可能消失。此时应保留全局暂停。

## 6. 对“人工有效”的强检验

建议保留报告 A-D，并增强自动修复组 B：

- 加入在规则模型内可直接执行的求解器修复。
- 提供额外自动重规划/推理预算的对照，并记录资源消耗。
- 增加“请求重规划但不提供人类修改”的控制。
- 使用同一干预前缀、匹配后续采样协议和多次继续执行，避免只对比一次成功轨迹。
- 真实人审使用同样的信息边界；环境真值仅作离线评估。
- 人工批准、校验通过、局部进展、问题恢复、最终完成分别记录。
- 按整局统计，处理重复地图与重复审阅者，不把一局中的多次事件当独立样本。

预算请求数相同不等于人工时间相同。全量审阅是更大编辑容量的参考；范围策略比较要统一编辑容量与请求限额。冻结快照的强制审阅与在线允许弃权的策略应分开评价。

## 7. 开工前先验证机制需求

建议先收集约 30-50 个自然失败或停滞快照，再补支持性规则内的受控反例。这个数量用于工程性筛查，不是正式统计功效保证。

记录：

1. 缺陷需要至少两个计划共同修改的比例。
2. 原有选择范围中，在声明模型和时域内不可修复的比例。
3. 自动执行候选改法后仍未恢复的比例。
4. 因未知事实而无法判断的比例。
5. 真实人审的阅读、修改及等待时间。
6. 审阅期间仍有多少无关工作可以推进。

受控反例解释机制；自然失败和留出场景检验实际适用性。若联合修改很少，优先检查 CUBE 的参与及时序任务是否覆盖了研究对象，不用重复制造容易证明的异常案例替代分布证据。

权重、阈值、规划时域和延迟设置在预实验后冻结，留出地图、资源布局、参与要求和审阅者用于正式评价。

## 8. 建议的实现顺序

1. 完成版本化剩余计划和统一执行事件，覆盖正在执行的承诺。
2. 建立约束模型及强自动修复基线 B。
3. 实现报告原有的完整集合选择，作为明确可复现的参照。
4. 加入权限域下的范围生成与可修复性检查。
5. 用证据组织审阅界面，采集真实时间与执行结果。
6. 完成 A-D、选择策略和必要性消融。
7. 只有等待损失足够明显时，再做局部暂停。

AgentScope 负责 Agent 生命周期、消息和异步模型接口。约束检查、范围选择、审阅事务和执行追踪保留独立模块，便于替换选择器和做消融。

## 9. 可供最终报告使用的贡献草案

以下均为研究计划，须按结果改写：

- 提出一种受字段编辑权限和联合任务约束限制的审阅范围生成方法，区分模型内可修复、不可修复与未知情况。
- 研究与该范围对应的证据组织方式，检验相较全量上下文和等长度摘要是否改善真实人工时间与修复质量。
- 在 MA-Crafter、CUBE 中，对强自动修复、全量人审和多种选择策略进行信息、容量与预算匹配的执行验证，明确有效与失效条件。

“保证选择的人类一定能修好”“首次使用超图/SMT/事务”“审批通过即成功”均不应成为结论。若求解器自动修复已取得同样效果，应报告人工环节没有额外收益，并将贡献定位到范围生成、诊断或执行协议。
