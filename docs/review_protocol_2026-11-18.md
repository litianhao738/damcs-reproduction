# 审阅规程

日期：2026-11-18。适用于表 1 的 H1、H2 和表 3 的 H2 真人审阅。所有审阅者按同一份规程操作，否则不同人的结果无法比较。

## 1. 你在做什么

程序在跑多智能体挖钻石（或推箱子）。当几个 AI 的计划出现协调问题、系统自己又没能解决时，会把一部分计划开放给你修改。你的任务是：在网页上看清问题，选择采用、修改或跳过，并尽快提交。

系统只在**关键时刻**问你，不限次数。关键时刻有三种，页面上会告诉你是哪一种：

- **要做取舍**：有好几个 Agent 都能帮上忙，需要你决定让谁去。下拉框里会同时开放这几个 Agent。
- **拿不准**：系统缺少信息，判断不了能不能修好。没有推荐方案，需要你看依据自己判断。
- **团队卡住**：团队已经 30 步没有新进展。

其余问题系统自动处理，不会问你。同一个问题问过之后，10 步内不会重复问。

所以一局里可能一次都不问，也可能问好几次，开跑后要一直留意提醒。你审阅期间，相关的 AI 原地等待，游戏时间照常流逝，所以**审得越慢，团队损失越大**。

## 2. 开跑前

1. 拉取最新代码，确认和其他审阅者是同一个提交：

   ```powershell
   git pull
   git log --oneline -1
   ```

   把显示的提交号报给负责人核对。开跑后不要再修改代码或配置文件。
2. 在 `mcrafter` 环境里执行命令。
3. 用 Chrome 或 Edge 打开审阅页面。关掉会弹窗、会让电脑休眠或自动更新重启的东西。一局可能持续很久，具体时长以试跑结果为准。
4. 同一台电脑同一时间只跑一个审阅任务，审阅页面占用固定端口 8765。
5. 记住负责人分配给你的**审阅者编号**（如 `R1`）和**种子**。

## 3. 先做一局练习

正式开始前，每人先跑一局练习，熟悉页面。练习局不计入结果。

```powershell
python scripts\run_experiments.py --model_profiles qwen --conditions H2 --seeds 99 --step_num 60 --review_trigger all --reviewer human --reviewer_id R1-practice --results_dir results\practice_R1
```

把 `R1` 换成自己的编号。练习局加了 `--review_trigger all`，遇到任何问题都会问你，这样前 60 步就能练到；正式运行不加这个参数，只在关键时刻问。如果 60 步内仍没有出现审阅请求，再跑一局或把 `--step_num` 加大。

## 4. 正式运行

把命令里的种子、编号和结果目录换成自己的。

**条件顺序要轮换**，避免"越审越熟练"只让某一个条件受益：

| 审阅者编号 | 表 1 的条件顺序 |
| --- | --- |
| 单号（R1、R3…） | `--conditions H1 H2` |
| 双号（R2、R4…） | `--conditions H2 H1` |

```powershell
# 表 1，Crafter（单号审阅者示例）
python scripts\run_experiments.py --model_profiles qwen --conditions H1 H2 --seeds 4 --repeats 2 --reviewer human --reviewer_id R1 --results_dir results\table1_crafter_human_R1

# 表 1，CUBE（只有 H2）
python scripts\run_experiments.py --environment cube --agent_num 3 --step_num 30 --model_profiles qwen --conditions H2 --seeds 4 --repeats 2 --reviewer human --reviewer_id R1 --results_dir results\table1_cube_human_R1
```

表 3 的模型顺序也要轮换，按负责人分配的顺序填写 `--model_profiles`。例如：

| 审阅者 | 模型顺序 |
| --- | --- |
| R1 | `deepseek kimi glm gpt` |
| R2 | `gpt glm kimi deepseek` |
| R3 | `kimi gpt deepseek glm` |

```powershell
python scripts\run_experiments.py --model_profiles deepseek kimi glm gpt --conditions H2 --seeds 4 --repeats 1 --reviewer human --reviewer_id R1 --results_dir results\table3_human_R1
```

## 5. 页面设置（每次开跑后都要做）

1. 命令开始运行后，打开 `http://127.0.0.1:8765`。
2. 点一次 **"开启声音和桌面提醒"**；浏览器询问是否允许通知时，选"允许"。
3. **保持"新请求到达时自动打开"处于勾选状态，不要取消。** 阅读时间从请求页面打开时开始计算；所有人都勾选，计时才一致。
4. 保持这个页面开着，不需要手动刷新。两局之间页面会短暂显示"连不上"，这是正常的，下一局开始后会自动接上。

## 6. 收到请求后怎么审

请求到达时会有提示音、桌面通知，页面会自动打开。按下面的顺序看：

1. **目标**：页面顶部写着哪个 Agent 想做什么没做成，例如"Agent 0: make wood_pickaxe"。
2. **倒计时**：总共 120 秒。**尽量在 60 秒内提交。**
3. **计划表**：开放给你的 Agent、它们的原计划、下拉框里能选的计划。
4. **推荐方案**：如果有，已经默认选在下拉框里。
5. **判断依据**：各 Agent 的背包、位置和周围的格子，需要时展开看。

### 判断标准

按下面的顺序判断，所有人用同一套标准，不因为条件不同而改变。

**第 1 条：推荐方案会不会伤害更重要的工作？**

以下情况视为有害，不要采用：

- 让一个正在做铁镐、或正在去采钻石的 Agent 停下来；
- 让某个 Agent 把自己马上要用的工具或材料给出去，例如把唯一的石镐送走后，自己就采不了铁。

**第 2 条：有没有明显更好的选项？**

只有当你确信下拉框里另一个选项更好时才修改。常见的更好选项是：改由空闲的 Agent（原计划是 `noop` 或在远处闲逛）或有多余材料的 Agent 来帮忙。

**第 3 条：按结论操作。**

| 情况 | 操作 |
| --- | --- |
| 推荐方案无害 | 点 **采用推荐方案** |
| 推荐方案有害，或你确信另一个选项更好 | 在下拉框里改选，点 **检查所选计划**。结果是 `repairable` 才点 **提交所选计划**；结果是 `infeasible` 或 `unknown` 时不要提交，改回推荐方案或跳过 |
| 没有推荐方案 | 在下拉框里找一个选项，点 **检查所选计划**。能通过就提交；找不到能通过的就跳过 |
| 看不懂、拿不准 | 点 **跳过此次审阅**，系统会自动处理。不要猜着改 |

补充说明：

- **"检查所选计划"可以点很多次**，不算提交。
- **检查不通过的修改不要提交。** 提交后系统还会复核，不通过的修改一定会被拒绝，只会白白浪费时间。
- **不要为了"用掉这次机会"而修改。** 跳过也是有效的判断。
- 提交后无法撤回。

## 7. 不要做的事

- 不要和其他审阅者讨论具体某一局的情况，也不要互相看对方的屏幕。
- 不要刻意去查当前跑的是哪个条件或哪个模型，按同一套标准审即可。
- 超时后页面会禁用按钮，迟到的回复会被拒绝，不要试图补交。
- 运行期间不要关闭终端窗口，不要让电脑休眠。
- 不要删除或改动 `results\` 下的任何结果目录，包括出错的局。

## 8. 出问题怎么办

| 现象 | 处理 |
| --- | --- |
| 页面显示"暂时连不上运行程序" | 两局之间的正常现象，等待即可。若持续超过几分钟，看终端是否报错 |
| 没有提示音 | 每次重新打开页面后都要再点一次"开启声音和桌面提醒" |
| 终端报错、运行中断 | 不要删除结果目录，截图终端，记入登记表并告诉负责人 |
| 端口 8765 被占用 | 确认没有另一个审阅任务在运行；仍有问题告诉负责人 |
| 点错了按钮 | 无法撤回，在登记表里写明是哪一局、哪个请求、点错了什么 |
| 有事必须离开 | 不要在一局中途离开。若无法避免，记录离开的时间段 |

| 审阅者编号 | 日期 | 开始时间 | 结束时间 | 表 | 环境 | 模型 | 条件 | 种子 | 重复编号 | 异常情况 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| R1 | 2026-11-20 | 14:05 | 15:40 | 表 1 | Crafter | qwen | H1 | 4 | 0 | 无 |

结果目录名里有条件、种子和重复编号，例如 `qwen_H1_seed4_r0_...`，可以直接照抄。阅读时间、提交内容等由程序自动记录，不需要手填。
