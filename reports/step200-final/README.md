# DAMCS 200 步正式实验结果

共核验 **36/36 局有效实验**，含原批次 34 局和 H-Q 补跑 2 局。六个条件各有 6 局，使用地图种子 4、5、6，每个种子重复 2 次。表 1 与表 2 共用 B、C 的结果。

**主要结果**。全自动修复机制 C 的平均采钻步数最低，为 **104.8 步**，成功 **4/6 局**。表 2 中，加入进度修复对应的 **C 对 B** 差异最大，C 平均少用 **38.2 步**，任务成功由 **3/6** 提高到 **4/6**。表 1 中，Qwen 审阅 H-Q 的修复成功率达到 **62/62**，但与 C 的采钻成功局数相同，平均多用 **12.0 步**。

- **B 对 A**。B 平均多用 14.2 步，采钻成功少 1 局。单独加入合法性修复时，本批次没有观察到采钻表现改善。
- **C 对 B**。配对差为 −38.2 ± 43.2 步，3 张地图中有 2 张在两次重复取均值后更快。
- **H-Q 对 C**。修复成功率提高约 3.6 个百分点，采钻成功仍是 4/6。按地图配对，H-Q 平均多用 12.00 ± 20.78 步，3 张地图均未显示平均步数下降。端到端耗时平均增加 180.38 ± 403.45 秒，每局增加 95.83 ± 32.11 个 Agent 暂停步。6 局共发出 29 次请求，收到 28 次回复，超时 1 次。以上为 Qwen 外部模型审阅结果。
- **补跑的 H-Q 第 5、6 局**。地图种子 6 的两次重复分别在第 **54**、**50** 步采钻，各发出 3 次审阅请求，全部收到回复，均无超时。

## 表 2：模块消融

| 条件 | 有效局数 | 采钻步数 ↓ | 采钻成功 | 里程碑数 ↑ | 停滞步数 ↓ | API 按量等效费用（CNY/局） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| C：全自动修复系统 | 6/6 | **104.8 ± 74.5** | 4/6 | 9.7 ± 0.5 | 40.5 ± 62.7 | 19.7978 ± 17.3476 |
| C-no-legality：去掉合法性修复 | 6/6 | 106.3 ± 73.7 | 4/6 | 9.7 ± 0.5 | 37.0 ± 57.3 | 15.7529 ± 13.4919 |
| B：去掉进度修复 | 6/6 | 143.0 ± 63.0 | 3/6 | 9.5 ± 0.5 | 33.7 ± 39.2 | 25.3496 ± 11.9300 |
| C-no-llm：独立规则规划器 | 6/6 | 136.7 ± 49.3 | 4/6 | 9.7 ± 0.5 | 29.7 ± 44.4 | 0.0000 ± 0.0000 |

- **合法性修复**。C 比 C-no-legality 平均少 1.5 步，按地图的配对差为 −1.5 ± 8.4 步，成功局数相同。这个差异在本批次较小。
- **进度修复**。去掉它后，平均采钻步数从 104.8 增至 143.0，成功局数从 4 降至 3。这是表 2 中平均步数降幅最大的模块对照。
- **独立规则规划器**。6 局均无聊天或嵌入 API 调用，64/64 个锁定任务完成，4/6 局采钻。与 C 相比，成功局数相同，平均多用 31.8 步。这一行衡量关闭 LLM 后规则规划器的独立表现。

原表与规则规划器逐局明细见 [表 2 CSV](paper/table2.csv) 和 [规则规划器逐局结果](paper/rule_planner_episodes.csv)。

## 统计口径与目录

- 表中的“±”为样本标准差。任务在限步内未采到钻石时，采钻步数按 200 计入均值。技术失败或未完成局与任务失败分别记录。最终矩阵的技术失败、未完成和缺失局数均为 0。
- 单条件表格按 6 局汇总。配对结果先在每张地图上对两次重复取均值，再对 3 张地图汇总。这里报告的是本批次观察到的差异，样本仅覆盖 3 个地图种子。
- API 费用列是 GLM 与嵌入调用的按量等效估算。归档报告记录，最后两局在补充 Token Plan 额度后重跑。Qwen 审阅用量单独记录，40 次 API 尝试共返回 66,912 tokens 的用量统计，未加到表格的人民币估算中。
